# 结婚好日子 · 自测报告（第七轮：产品化收口 + 视觉去呆板）

测试日期：2026-11-14　环境：Chrome 157（headless）+ Node 24

## 这轮补的是「产品完整度」，不是新功能

| # | 缺口 | 做法 |
| --- | --- | --- |
| 1 | 海报没有入口，转发出去是死路 | 海报右下角加**二维码**，扫码回到本页，且带上你们的生日 |
| 2 | 分享按钮埋在页面最底部 | 结果区红标题块里加**四个快速动作**：存成一张图 / 复制分享链接 / 发电子请柬 / 打印择日帖 |
| 3 | 链接发出去，对方打开是空表单 | 把六人生日、时辰、范围、偏好编码进 `#q=`，**打开即还原并直接出结果** |
| 4 | 页面自称依据通书，但没有版本 | 结果区加**规则表 v1.0**，页脚同步版本号 |
| 5 | 文案有工程师腔（「用时 37 毫秒」） | 改成「从 365 天里挑出 61 个可用的日子」；表单提示改成「两分钟填完」 |

## 这轮验证过的

- 复制链接后在新标签打开：三张卡片直接出现，新郎生日还原为 1994-03-18，不需要重新填。
- 海报二维码内容为当前页面完整地址（含 `#q=`），扫码即回到同一结果。
- 打印时快速动作、规则版本行、二维码都会被隐藏，不影响帖面。

## 第八轮：去呆板

| 问题 | 改法 |
| --- | --- |
| 首屏是「两栏文字 + 一张卡」，像网页模板 | 标题改**竖排**，占满左侧一条书脊；正文、按钮、通书卡依次右移，形成不对称版式 |
| 三张日子牌一样大一样正，没有层次 | 改成**错落叠放**：-3° / +0.8° / +3°，上下错开，首选最高；鼠标悬停会扶正并抬起 |
| 页面没有任何「婚礼」的形状 | 在卡片上方加一条**红线**（SVG 弧线 + 结），日子像挂在线上 |
| 通书卡在窄栏里文字挤压换行 | 卡内改成竖排堆叠（日 → 农历 → 干支），不再挤成三行 |
| 移动端封面出现大片空白 | 竖排标题在窄屏回退为横排，并清掉 `min-height`（这轮实测发现并修掉） |

## 还没做（交付前建议补）

- 没有真实的线上域名，二维码指向本地地址；上线后需替换为正式域名并做一次全链路复测；
- 没有微信内分享卡片（需要公众号 JS-SDK 与域名备案）；
- 分享链接里含生日，属于个人信息——正式上线应在分享前加一句提示，或提供「脱敏分享」（只带结果、不带生日）。
